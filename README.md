# 暗号化生成パイプライン（汎用版） / Encrypted Generation Pipeline

「生成して、でも中身は見ないで暗号化して」を実現するための、
[muse.ai](https://muse.ai) 向け配布パッケージです。

画像・動画・音声・テキストを生成AIに作らせるとき、生成物そのものを
チャットに表示すると、その分だけAIのコンテキスト（トークン）を消費します。
このパイプラインでは、生成物を**開かず・表示せず・添付せず**に暗号化し、
AIが受け取るのは「領収書」（メタ情報）だけにすることで、トークン消費を抑えつつ、
受け取った人だけが復号できる形で生成物を届けます。

このリポジトリには、個人のアカウント・鍵・利用履歴などのデータは一切含まれていません。
鍵もジョブも空の状態から、各利用者が自分の環境で始めるための汎用版です。

## これはどういうアーティファクトか

中心になるのは、muse.ai の環境に作る**ウェブアーティファクト
『暗号化生成パイプライン』**です。全体は2層構成になっています。

| 層 | 役割 |
|---|---|
| **アーティファクト（司令塔）** | 鍵の登録・切り替え、生成ジョブの受け付け、領収書の台帳、ブラウザ内暗号化ツール。データは利用者本人の Muse 環境の中だけに保存されます |
| **Pythonエンジン（実行部）** `lenc-pipeline/lenc.py` | 生成された実ファイルを受け取り、暗号化／復号を行うコマンドラインツール。アーティファクトと共通の `.lenc` v1 形式を使うので、どちらで暗号化しても他方で復号できます |

### アーティファクトのタブ

1. **鍵** — 方式（RSA-2048 / RSA-4096 / Ed25519 / Ed448 / ML-KEM-768 / ML-KEM-1024）と
   `key_id`、役割（暗号化用公開鍵／復号用秘密鍵／署名鍵）を指定して鍵を登録。
   有効鍵の切り替え（ローテーション）もここで行います。
   一覧に表示されるのは SHA-256 フィンガープリントとメタ情報だけで、
   **鍵の中身や秘密鍵は二度と表示されません**。
   出力形式に `.gpg` を使う場合は、宛先として OpenPGP 公開鍵ブロック
   （RSA や Ed25519 などの鍵）を、対応する方式のラベルで登録できます。
2. **生成ジョブ** — 種別（画像／動画／音声／テキスト）と生成指示、暗号化方式を登録し、
   （ここでいう「音声」は特定の形式を指しません。WAV / OGG / MP3 / M4A / FLAC / AAC / Opus など、
   あらゆる音声ファイル形式を含みます。暗号化エンジンはファイルをバイナリの流れとして扱うため、
   拡張子やコンテナ形式を問いません。画像・動画・テキストについても同様に形式不問です）
   状態（queued → generated → encrypted → done / failed）を管理します。
   ジョブごとに、暗号化の出力形式（`.lenc` または `.gpg`）も選べます。
   チャットから AI に頼んだ内容も、AI がこのタブへジョブとして登録できます。
   登録したジョブには **「実行を依頼」ボタン** があり、押すと自分の Muse
   （AIコンパニオン）へバックグラウンドで実行が依頼され、生成 → 暗号化 →
   暗号化ファイルの受け渡し → 状態と領収書の報告まで進みます
   （依頼済みのジョブには依頼日時が表示され、二重に依頼はできません）。
   繰り返し登場させたい被写体がある場合は、利用者自身が「被写体プロフィール」
   （参照画像や外見の説明文）を任意で登録できます（初期状態は空で、
   特定の人物・キャラクターがあらかじめ登録されていることはありません）。
3. **暗号化ツール** — ブラウザの中だけで完結する暗号化／復号ツール。
   全6方式に対応し、Python版と相互に復号できます（対象は `.lenc` 形式です。
   `.gpg` の暗号化は実行側が行います）。
4. **領収書** — 暗号化の記録台帳。保存されるのは方式・出力形式・`key_id`・入出力サイズ・
   暗号文の SHA-256・署名の有無・所要秒数だけで、**ファイルの中身は保存されません**。
5. **配布** — このパッケージ自体の案内（リポジトリ、導入手順、ライセンス要約）。

### 生成バックエンドについて（自分の生成AIの追加方法）

ジョブの「生成バックエンド」は、生成を担当するAIの指定です。最初からあるのは次の3つだけです。

- `muse-image` / `muse-video` — 利用者本人の Muse 環境に組み込みの画像／動画生成
- `external` — それ以外の生成AIを、名前なしで使うときの受け皿

**自分が使っている生成AI（画像・音楽・動画など）を名前で使いたい場合は、
生成ジョブタブの「自分の生成AIをバックエンドとして登録」から登録します。**
登録するのは、名前（自分が使う生成サービスの名前など）・対応するメディア種別・
接続方法の備考（自分の Muse がその環境でどう呼ぶか：接続済みのツールやAPI、
ローカルにあるヘルパープログラム、ステージングフォルダへファイルを置く約束、など）です。

登録すると何が起きるか：

- その名前が、ジョブ作成フォームのバックエンド選択肢に追加されます
  （ジョブのメディア種別に対応するものだけが候補に出ます）
- その名前で作ったジョブには名前が記録され、ジョブ一覧にも表示されます。
  実行側の Muse は、その名前と備考を見て、指定された生成AIで生成します
- 登録を削除しても、作成済みのジョブに記録された名前は残ります
  （消えるのは今後の選択肢からだけです）

組み込みの汎用項目 `external` 自体も、不要なら削除できます。自分の生成AIを
登録したあと、バックエンド登録のセクションで「外部ジェネレータ（組み込み）」を
削除すると、選択肢から消えて、名前なしの外部ジョブは作れなくなります
（登録済みバックエンドでのジョブ作成はそのままできます）。
削除の状態は保存され、「元に戻す」でいつでも復活できます。
作成済みのジョブの記録には影響しません。

登録しても起きないこと（重要）：

- **アーティファクト自体が生成AIを呼び出すことはありません。**
  登録は「選択肢への追加」と「ジョブへの記録」だけです
- **名前を登録しただけでは、その生成サービスへの接続は完結しません。**
  生成AIは、利用者本人の Muse 環境ですでに使える状態
  （サービスへの接続、APIの利用権、ヘルパープログラムの導入など）である必要があります
- **APIキーなどの資格情報は、バックエンド登録には保存しません。**
  接続情報は各サービスの正規の方法で、自分の環境側に保管してください

### 暗号の仕組み（全方式ハイブリッド暗号化）

- 本体は常に、ランダムな 256bit 鍵による **AES-256-GCM**（1MiB 単位の分割で、
  大きな動画でも一定メモリで処理できます）。
- 指定した方式は、その鍵を包む（ラップする）役割を担います。

| 指定 | 実体 |
|---|---|
| `rsa2048` / `rsa4096` | RSA-OAEP（SHA-256）で鍵をラップ |
| `mlkem768` / `mlkem1024` | ML-KEM（FIPS 203、いわゆる Kyber）: KEM の共有秘密 → HKDF → ラップ用鍵 |
| `ed25519` / `ed448` | ※EdDSA は署名専用で暗号化できません。この指定は「X25519 / X448 の ECDH で鍵をラップし、Ed25519 / Ed448 の署名を必須で付ける」プリセットです |

- 容器は `.lenc` v1 形式：1行目が JSON ヘッダ（方式と `key_id` など、平文の情報は含みません）、
  続いて暗号文、署名がある場合は末尾に署名が付きます。

### 出力形式：`.lenc` と `.gpg`

ジョブごとに、暗号化ファイルの形式を選べます。

- **`.lenc`** — このパッケージ独自の形式（上の仕組み）。アーティファクト内蔵ツールと
  Python エンジンのどちらでも暗号化／復号できます
- **`.gpg`** — 標準の OpenPGP メッセージ。登録した OpenPGP 公開鍵
  （RSA・Ed25519/X25519・Ed448/X448 など）宛てに暗号化され、通常の GPG ツールと
  自分の PGP 秘密鍵で復号できます。RSA や Ed 系の鍵を使う人にはこちらが自然です。
  `.gpg` の暗号化は実行側（Muse コンパニオン／環境側の GPG）が行い、
  Python エンジン `lenc.py` 自体は `.lenc` 専用です

どちらの形式で作ったかは、ジョブと領収書の両方に記録されます。

## muse.ai を使っている人向け：導入のしかた

詳しくは [`INSTALL_FOR_MUSE.md`](INSTALL_FOR_MUSE.md) を参照してください。概要は次のとおりです。

1. このリポジトリをダウンロードします（GitHub の **Code → Download ZIP**、または clone）。
2. 自分の Muse のチャットに ZIP（または展開したフォルダ）を渡して、こう頼みます：

   > これは暗号化生成パイプラインの配布パッケージです。
   > `INSTALL_FOR_MUSE.md` と `artifact/ARTIFACT_SPEC.md` を読んで、
   > 仕様どおりにアーティファクトを作成し（データは空で）、
   > `lenc-pipeline/` の Python エンジンを私のワークスペースに導入してください。

3. 自分の Muse が、アーティファクトの作成と Python エンジンの導入・動作確認
   （`run_tests.py` で 24件全PASS＋ローテーションPASS が目安）まで行います。
4. 鍵タブで自分の鍵ペアを生成するか、自分の公開鍵を登録します。
   **原則として、AI に渡すのは公開鍵だけにしてください。** 復号用の秘密鍵は自分の手元に置きます。

環境ごとにアーティファクト・鍵・領収書は完全に分離されます。
他人の環境と混ざることはありません。

## 使い方

### チャットから（通常の使い方）

自分の Muse に、暗号化したいことを明示して頼みます。例：

- 「〜の画像を生成して、RSA-2048 で暗号化して」
- 「この文章をテキストとして生成して、Ed25519 で暗号化して」

すると Muse がジョブを登録 → 生成 → 中身を見ずに暗号化 → 領収書を記録し、
暗号化ファイル（`.lenc`、または鍵の形式によっては `.gpg` 等）を届けます。
復号は自分の秘密鍵で行います。

アーティファクトの画面で自分でジョブを登録した場合は、ジョブ一覧の
**「実行を依頼」ボタン**を押せば、同じ流れを Muse へ依頼できます。

### Python エンジンを直接使う

```bash
cd lenc-pipeline
./setup.sh   # このフォルダ内に venv を作って依存を入れる

# 鍵の生成と有効化
.venv/bin/python lenc.py keygen --alg rsa2048 --key-id mykey1 --keys keys

# 暗号化（出力されるのは領収書 JSON だけ）
.venv/bin/python lenc.py encrypt --alg rsa2048 --infile <生成ファイル> --out <出力.lenc> --keys keys

# 復号（ヘッダの key_id から鍵を自動選択）
.venv/bin/python lenc.py decrypt --infile <ファイル.lenc> --out <復元ファイル> --keys keys

# 動作確認（ダミー生成→暗号化→復号を自動検証）
.venv/bin/python run_tests.py
```

### 鍵の変更（ローテーション）

新しい鍵を生成・登録して有効化するだけです。各ファイルのヘッダに `key_id` が
記録されているため、差し替え前に作ったファイルも、対応する秘密鍵で後から復号できます。
